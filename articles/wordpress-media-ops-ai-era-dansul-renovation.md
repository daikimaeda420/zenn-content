# はじめに

![生成AI時代における、WordPressのメディア運用と改修](https://raw.githubusercontent.com/daikimaeda420/zenn-content/main/images/codex-articles/wordpress-media-ops-ai-era-thumbnail.png)

生成AIでコードを書けるようになると、Webメディアの改修速度はかなり上がります。

一方で、WordPressのように長く運用しているメディアでは、速度だけを上げると危険です。1つのテンプレート修正が、数百ページの表示、SEO、予約導線、管理画面の運用に一気に波及するからです。

この記事では、ダンススクール比較メディア「ダンスル」で行ったWordPress改修を例に、生成AI時代のメディア運用で何を設計し、どこに気をつけたかをまとめます。

対象にした主なページは次の通りです。

- [トップページ](https://dansul.jp/test/)
- [エリア総合ページ](https://dansul.jp/area/)
- [都道府県ページ](https://dansul.jp/area/osaka/)
- [市町村ページ](https://dansul.jp/area/osaka/osaka/)
- [駅・沿線総合ページ](https://dansul.jp/station/)
- [梅田駅ページ](https://dansul.jp/station/osaka/umeda/)
- [教室詳細ページ 有料版](https://dansul.jp/school/etc-osaka/)
- [教室詳細ページ 無料版](https://dansul.jp/school/noa-dance-academy/)

# WordPressを「記事CMS」ではなく「メディアOS」として扱う

今回の改修で強く感じたのは、WordPressを単なる記事投稿ツールとして見ると設計を間違えやすい、ということです。

ダンスルでは、記事だけでなく、次のような情報が混ざっています。

- 教室詳細データ
- 都道府県、エリア、市区町村、駅
- 料金、体験料、対象年齢、ジャンル
- 口コミ、評価、FAQ
- 予約CTA
- 有料掲載と無料掲載の表示差
- JSON同期データ
- 管理画面で編集する投稿メタ

つまり、WordPressは「編集画面」「URL設計」「SEO」「テンプレート」「データ同期」をまとめて扱うメディアOSのような存在です。

生成AIに任せる場合も、単発のHTMLを作らせるだけでは足りません。どの情報をWordPress側に持たせ、どの情報をJSONで同期し、どの情報をテンプレートで動的に表示するかを決める必要があります。

# 改修したページ群

## トップページ

[トップページ](https://dansul.jp/test/) は、単なる入口ではなく、ユーザーが最初に検索軸を選ぶ場所として作り直しました。

主な導線は次の通りです。

- エリアから探す
- 駅・沿線から探す
- 目的・条件から探す
- 人気スクール、口コミ、監修者情報

トップで重要だったのは、見た目の華やかさよりも「検索の最初の一手」を迷わせないことです。

ファーストビューでは、ブランド感を出しつつ、無料体験、駅・沿線、年代、ジャンルなどの入口をすぐ押せるようにしました。

## エリア総合ページ

[エリア総合ページ](https://dansul.jp/area/) では、全国の都道府県を地域ブロックごとに整理しました。

ここはSEO上も重要です。都道府県ページへ内部リンクを流すハブであり、ユーザーにとっては「まず自分の地域を選ぶ」入口になります。

改修では、地域ブロックごとに色を分け、カード全体をクリックできるようにしました。小さなテキストリンクだけにすると、スマホで押しにくくなります。

## 都道府県ページ・市町村ページ

[大阪府ページ](https://dansul.jp/area/osaka/) と [大阪市ページ](https://dansul.jp/area/osaka/osaka/) では、一覧ページとしての使いやすさを重視しました。

特に大きかったのはフィルターです。

- ジャンル
- 対象年代
- レベル
- レッスン形式
- 特徴
- 料金帯
- 市・エリア

最初はJSONの `filters` に入っている値だけで絞り込む設計でした。しかし実データでは、すべての教室に `filters` が揃っているわけではありません。

そこで、次のようなフォールバックを追加しました。

- `filters` があれば優先
- なければタグ、説明文、料金、駅徒歩情報から判定
- その地域に存在しない選択肢はフィルターに出さない

メディア運用では、「正規化されたデータだけで理想的に動く」よりも、「現実のデータの欠けを吸収して動く」ことが大切です。

## 駅・沿線ページ

[駅・沿線総合ページ](https://dansul.jp/station/) と [梅田駅ページ](https://dansul.jp/station/osaka/umeda/) では、エリアとは別の検索軸を作りました。

ダンススクール探しでは、都道府県よりも「通える駅」の方が意思決定に近いことがあります。

駅ページでは、次の情報を出すようにしました。

- 駅周辺の掲載数
- 無料体験あり
- 駅徒歩5分以内
- 教室一覧
- 近隣駅・関連エリアへの導線

同じスクール一覧でも、都道府県ページと駅ページで使い回せる部分と、見出し・導線・統計のように変えるべき部分を分けています。

# 教室詳細ページは有料版と無料版を分ける

教室詳細ページは、有料版と無料版で役割が違います。

## 有料版

[有料版の例](https://dansul.jp/school/etc-osaka/) では、教室の魅力をしっかり伝えるために、以下の情報を出せるようにしました。

- メイン画像、ギャラリー
- 料金カード
- コース別料金
- 講師紹介
- スケジュール
- ジャンル・クラス
- 口コミ
- FAQ
- 体験予約CTA
- ポップアップ予約フォーム
- 外部予約URL

有料掲載では「予約に進む」ことが目的なので、CTAや予約フォームの出し分けも重要です。

教室ごとに、管理画面で通知先メール、自動返信文面、予約フォーム方式を設定できるようにしました。

## 無料版

[無料版の例](https://dansul.jp/school/noa-dance-academy/) では、公開情報をもとにした紹介ページとして設計しました。

無料版では、過剰に予約導線を作り込むよりも、公式サイトや公開情報への導線を明確にする方が適しています。

同じ「教室詳細」でも、ビジネス上の役割が違うため、テンプレートも分ける必要があります。

# JSON同期とWordPress管理画面の役割分担

今回の改修では、`data/dance-schools/*.json` とWordPress投稿メタの同期も大きなテーマでした。

基本方針は次の通りです。

- 教室の公開情報はJSONで管理できるようにする
- WordPress管理画面で編集したい項目は投稿メタに持たせる
- メールアドレスなど、リポジトリに入れたくない情報はJSON同期対象にしない
- どのJSONから読み込まれたかを管理画面や表示上で追えるようにする

AIで大量のJSONを生成・整形できるようになると、データ投入はかなり速くなります。

ただし、同期対象を広げすぎると、管理画面で直した値が次の同期で上書きされます。逆に同期対象が狭すぎると、JSONを直してもフロントに反映されません。

この境界設計が、WordPressメディア運用ではかなり重要です。

# 生成AIで速くなる一方、事故も速くなる

今回、生成AIを使った改修で特に注意が必要だと感じたのは、共通テンプレートです。

たとえば、教室詳細ページの共通レンダラーで次のような処理を入れるとします。

```php
str_replace('500円', $trial_price, $html);
```

一見便利ですが、`3,500円` の中にも `500円` が含まれます。

その結果、`3,500円` が `3,3,500円` になるような事故が起きます。

また、評価が空のときに次のようなデフォルトを出すのも危険です。

```php
$stars = $rating_stars ?: '★★★★★';
```

データがないのに星5が表示されると、メディアとしての信頼性に直結します。

生成AIは実装速度を上げますが、共通テンプレートに入れる処理ほど、影響範囲を先に考える必要があります。

# 実装時に決めたルール

今回の改修では、次のルールを意識しました。

- 文字列置換は全文一致に限定する
- 空データに虚偽のデフォルト値を出さない
- JSONにない情報をテンプレート側で無理に作らない
- 有料版と無料版の責務を分ける
- フィルターはデータ欠けを想定してフォールバックする
- スマホの操作性を優先する
- 予約フォーム、通知メール、個人情報は管理画面側で扱う
- 変更後は対象URLを実際に確認する

特に「空なら出さない」は重要です。

メディアでは、見栄えのための仮データがそのまま本番に残ることがあります。AIで高速に実装していると、ここを見落としやすくなります。

# WordPress改修でAIに任せやすいこと

生成AIに任せやすかったのは、次のような作業です。

- 既存テンプレートの読み取り
- レスポンシブUIの調整
- PHPのレンダリング関数整理
- JSONスキーマに沿ったデータ変換
- 管理画面項目の追加
- 検証コマンドの作成
- 変更レポートの作成

一方で、AIに丸投げしない方がよいのは次の判断です。

- どのデータを正とするか
- 有料版と無料版の責務
- 予約導線のビジネス要件
- SEO上どのページをハブにするか
- どこまでをテンプレートで補完するか
- どの情報をJSONに入れないか

AIは実装の手を速くしてくれますが、メディアの運用方針までは自動で決めてくれません。

# まとめ

生成AI時代のWordPress改修では、「ページを作る」よりも「運用できる構造にする」ことが重要だと感じました。

トップページ、エリアページ、駅ページ、教室詳細ページをそれぞれ作るだけなら、AIでかなり速く進みます。

しかし、実際のメディアでは、データ同期、管理画面、SEO、予約導線、スマホUI、レビュー、構造化データ、チーム運用までつながっています。

WordPressは古い仕組みに見えることもありますが、編集・URL・SEO・管理画面をまとめて扱える点では、今でも強力です。

生成AIを使うなら、WordPressを「AIで雑に置き換える対象」と見るのではなく、「AIで運用レイヤーを強化する土台」として扱うのが現実的だと思います。
